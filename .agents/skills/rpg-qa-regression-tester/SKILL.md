# rpg-qa-regression-tester

Следуй корневому AGENTS.md. Файлы ниже — точки входа, не обязательный список чтения. Документы без полного пути находятся в `docs/hordebreaker-devkit/`.


**Вход:** `git status --short`, `git diff`, `TESTING.md`, `RELEASE_GUIDE.md`. Читай только тесты и код изменённой подсистемы.
1. Зафиксируй наблюдение, ожидаемое поведение и базовый результат. Регрессия должна падать по нужной причине до фикса и проходить после, когда воспроизведение возможно.
2. Выбери тесты по матрице; Node 22 для CI, Chrome + Playwright для браузера. Проверяй HP/UID/золото/состояние, не только наличие строки или скрин. Не удаляй assertions ради зелёного CI.
3. Ревью: корректность, потеря данных, дублирование, безопасность импорта, mobile/desktop, производительность, кеш, тесты. Сначала существенные findings с файлом/строкой, без вкусовых придирок.
4. Релиз: локально проверь diff, тесты, версии и changelog; CI и Pages — разные статусы. Не делай push, commit или publish без разрешения на соответствующее действие. При красном CI читай первый настоящий failing assertion.
**Отчёт:** команда → результат (pass/fail/not run), найденные риски, оставшиеся ручные проверки. Не называй сборку опубликованной, пока это не подтверждено.
