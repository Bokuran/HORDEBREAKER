# rpg-game-architect

Следуй корневому AGENTS.md. Файлы ниже — точки входа, не обязательный список чтения. Документы без полного пути находятся в `docs/hordebreaker-devkit/`.


**Вход:** `index.html`, `js/boot.js`, `js/main.js`; затем только нужный модуль из PROJECT.md. Для сохранений — `js/core.js`, `js/savetools.js`, `SAVE_SYSTEM.md`; для FPS — `PERFORMANCE.md`.
1. Определи владельца состояния (`T.S`), событий (`T.events`), конфигурации (`T.config`) и кадра (`T.battleState`). Проверь порядок загрузки скриптов; не добавляй framework/npm в runtime.
2. Изолируй изменение в существующем API, сохрани ID, публичные вызовы и семантику событий. Не делай большой рефакторинг ради маленькой задачи.
3. Миграция: резерв исходного JSON до записи, идемпотентность, защита от ошибки quota, неизвестные поля и старые UID. Никогда не очищай реальные сохранения ради теста.
4. Производительность: измерь базу и результат на одинаковой сцене; не оптимизируй на глаз. Раздели игровое dt, визуальное время и UI; не меняй RNG, урон или скорость ради FPS.
**Проверки:** `sanity.mjs`; для экипировки/миграции `balance-equipment.mjs`; для кадров/строя `formation.mjs`, `effects.mjs` по области. Отчёт: API/данные, совместимость, измерения и ограничения.
