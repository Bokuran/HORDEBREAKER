# Производительность

Главные точки: `js/main.js` (RAF, dt, UI tick, hidden), `battle.js` (update), `battle-draw.js`/`battle-fx.js` (Canvas), `core.js` (кеш изображений и derived), `ui.js` (DOM). Измеряй до изменения: устройство/браузер, размер экрана, волна, число сущностей, эффекты, скорость, одинаковое время прогона. FPS, p50/p95 frame time, долгие кадры, heap/рост объектов, число DOM-обновлений. Не обещай 60 FPS без замера.

1. Профилируй одну воспроизводимую сцену в DevTools Performance, например босс ×3 с четырьмя героями. Сравни равные условия.
2. Устрани лишние расчёты/аллоцирование, повторный decode, ненужные DOM-перерисовки. Ограничивай визуальные частицы отдельно от симуляции; очищай просроченные эффекты, не дублируй таймеры и слушатели.
3. Не меняй dt, RNG, cooldown, HP, начисления или дальность ради измерения FPS. Сохраняй корректное поведение вкладки hidden, reduced motion и DPR.
4. Проверяй formation.mjs, effects.mjs, monster-contact.mjs или journey.mjs по затронутому коду, sanity.mjs. Отчёт: baseline/после с условиями, ограничения, профили. Без замера — только гипотеза.
