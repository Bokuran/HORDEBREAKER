# Экономия контекста и лимитов Codex

Цель: меньше повторного чтения и ненужных циклов, не меньше качества. Точные лимиты, тарифы и стоимость моделей здесь не фиксируются; они меняются. Skills не бесплатны: описание и при активации содержимое занимают контекст.

## Практический процесс
1. ChatGPT: идея, спецификация, дизайн, арт; Codex: локальная реализация, тесты, дифф. Не веди одновременные правки GitHub и локальной ветки без синхронизации.
2. Одна задача = один проверяемый результат. Укажи основной `$rpg-...`, точки входа, что запрещено менять, acceptance tests. Группируй однотипные мелкие правки, не смешивай арт/экономику/рефакторинг без связи.
3. Начинай с низкого/среднего доступного effort для CSS/конфигов/известного пути. Повышай для сложного боя, миграции, гонок и архитектуры. Названия уровней зависят от клиента; это рекомендация, не настройка аккаунта.
4. `git status --short`, `git diff --stat`, точечный поиск `rg -n 'sweepAutoSell|spareItems' js/core.js js/autoequip.js`. Не проси прочитать весь репозиторий, огромные логи, бинарники, весь changelog. Читай нужный фрагмент лога первой ошибки. Не дублируй десять Skills.
5. Сначала один целевой тест; после изменения затронутых файлов повтори его. Полный sanity перед завершением, браузерные тесты по риску. Не повторяй всё после чисто текстовой правки.
6. После завершения сделай короткий handoff: цель, файлы, тесты, открытые риски, следующий шаг. При смене подсистемы начинай новую сессию; не бесконечное «продолжай». При лимите сохрани локальный diff и заметку, не начинай широкую задачу.

## Готовый запрос
```
Используй $rpg-combat-engineer. Исправь [наблюдение].
Вход: js/battle.js, js/battle-base.js. Не меняй баланс, арт и сохранения.
Критерий: [воспроизводимый сценарий и измеримый итог].
Добавь регрессию, запусти целевые тесты и sanity; дай краткий diff/report.
Не делай push. Остановись по достижении критериев.
```

Если нет `rg`, используй PowerShell Select-String с явными путями. Если Codex не видит Skill — проверь `.agents/skills/<name>/SKILL.md`, открой новую сессию проекта и выбери навык средствами клиента. Не заставляй читать все документы на каждый запрос.
