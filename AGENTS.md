# HORDEBREAKER — инструкции Codex

## Контекст и границы
- Браузерная idle-RPG: vanilla JS, HTML/CSS, Canvas, `window.TBH`; без сборщика и серверной части. Источник истины — текущий код локальной ветки, а не старый README.
- Перед работой: `git status --short`, прочитай задачу, выбери один основной Skill. Не читай весь репозиторий, историю, бинарные ассеты и все документы без причины. Карта входов: `docs/hordebreaker-devkit/PROJECT.md`.
- Изменяй минимальный набор файлов; расширяй область только если найденная зависимость требует этого. Не откатывай чужие изменения. Не меняй зависимости, архитектуру, баланс, дизайн, ID и формат сохранений без задачи.
- Не запускай `git push`, не создавай релиз и не меняй настройки GitHub без явного разрешения. Не используй `reset --hard`, `clean -fd`, force push. Не коммить секреты, сохранения и временные артефакты.

## Инварианты
- Сохраняй совместимость старых сохранений, UID предметов, прогресс, резерв, ручную экипировку и резервные копии. Миграция — проверяемая, однократная, с отказом при невозможности backup.
- Проверяй класс, слот, уровень в ядре; тяжёлая броня только у Паладина/Варвара. Автопродажа — по настройке игрока, без скрытой потери вещей или двойного начисления.
- Боевой урон и лечение идут через существующие функции. Таймеры тикают один раз; дальники атакуют видимую цель, ближники учитывают размеры и контакт; не подменяй исправление расширением хитбокса. FX не меняют исход боя.
- Сохраняй качественные WebP и гербы карты. Предметы без встроенной рамки, прозрачные, 256×256; рамка редкости только в UI. SVG — допустимый резерв, не замена живописной графики.

## Проверка и завершение
- Воспроизведи баг, если возможно; добавь регрессию. Проверь изменённые JS/MJS через `node --check`, затем релевантный тест. Перед готовностью к публикации — `node tests/sanity.mjs`; для UI/ассетов/боя также соответствующий Chrome-тест. Матрица: `docs/hordebreaker-devkit/TESTING.md`.
- Не повторяй зелёный тест без изменений его входов, но после исправления запускай затронутые проверки. Не удаляй тесты ради зелёного CI. Не выдавай отсутствие проверки за успех.
- Финал: причина/цель, изменения и файлы, фактические проверки, риски, что проверить вручную. Остановись после выполнения критериев, не продолжай незапрошенные улучшения.
